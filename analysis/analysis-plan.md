# Analysis Plan

## Purpose

This document defines the first analysis plan for the AI Half-Life research project.

The goal is to move from concept to evidence without overstating what the current data can prove.

## Current dataset status

Current dataset version: v0.1

The seed dataset includes verified public deployments and measurable outcome observations. It is not yet large enough for definitive statistical inference, but it is large enough to support early descriptive analysis and whitepaper framing.

## Primary research questions

1. What outcome categories are most often reported in public AI deployment case studies?
2. How often do sources report follow-up duration?
3. How often do sources report long-term value persistence?
4. How often do sources report recalibration, redesign, retirement, or value decay?
5. Are adoption and workflow outcomes reported more often than financial outcomes?
6. Do public case studies distinguish technical success from realized value?

## Descriptive analysis

Initial analysis should include:

- Count of deployments by industry
- Count of deployments by evidence tier
- Count of deployments by status classification
- Count of outcome observations by metric family
- Follow-up duration distribution
- Source type distribution
- Share of cases with financial outcomes
- Share of cases with adoption outcomes
- Share of cases with workflow outcomes
- Share of cases with technical performance outcomes
- Share of cases with explicit recalibration or retirement evidence

## Gap analysis

The central gap analysis should compare what is commonly measured versus what AI Half-Life needs.

Expected measurement categories:

- Technical performance
- Governance
- Safety
- Fairness and bias
- Adoption
- Workflow impact
- Financial value
- Clinical or operational outcome
- Long-term value persistence
- Explicit value decay
- Retirement criteria

## Candidate visualizations

1. Measurement coverage heatmap
2. Outcome observation bar chart
3. Evidence-tier distribution
4. Deployment status distribution
5. Follow-up duration distribution
6. Conceptual AI Half-Life decay curve
7. Sankey-style view from deployment to measured outcome category

## Survival analysis plan

Survival analysis should wait until the dataset contains enough cases with credible follow-up duration and event classification.

Potential event definitions:

- Value falls below 50 percent of baseline
- Adoption falls below threshold
- Financial benefit no longer exceeds cost
- System is recalibrated due to performance or value decline
- System is retired

Potential censoring:

- System still active at last public report
- Follow-up ended before value failure
- Source does not report later outcome

## Bias considerations

The dataset is likely affected by:

- Publication bias
- Survivorship bias
- Vendor reporting bias
- Positive outcome bias
- Short follow-up bias
- Industry transparency differences

The whitepaper should explicitly discuss these limitations.

## Near-term target

Dataset v1 should include at least 100 verified deployments.

Only after reaching that milestone should the project claim anything more than early descriptive findings.

## Long-term target

Dataset v2 should include 300 to 500 verified or graded deployments, with separate tiers for evidence quality.

At that point, the project may support more rigorous modeling of predictors of value persistence.
