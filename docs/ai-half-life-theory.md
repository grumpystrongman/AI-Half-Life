# AI Half-Life Theory

## Core idea

AI Half-Life is a proposed framework for measuring how long an AI system continues to create realized value after deployment.

The core claim is not that AI models suddenly stop working. The core claim is that value can decay even when technical performance remains acceptable.

A model may remain accurate while the workflow around it changes, user trust declines, leadership sponsorship moves elsewhere, adoption fades, financial return erodes, or governance monitoring becomes less active.

That is the gap this project is studying.

## Working definition

AI Half-Life is the amount of time required for an AI-enabled intervention to lose 50 percent of its realized value after deployment.

This is intentionally different from model performance half-life.

Model performance half-life asks whether accuracy, calibration, precision, recall, or other model metrics have deteriorated.

AI Half-Life asks whether the deployed system is still producing meaningful value in the real world.

## Why this matters

Most AI governance and monitoring frameworks are strong on responsible design, safety, bias, fairness, drift, and technical monitoring. Those are required. But they do not fully answer a leadership question:

When should we keep investing in this AI system, recalibrate it, redesign the workflow, restrict its use, or retire it?

Organizations often know whether a model is running. They may even know whether it is drifting. But they may not know whether the value case is still alive.

## Three layers of half-life

### 1. Statistical half-life

The period before model performance falls below an acceptable threshold.

Signals may include:

- Accuracy decline
- Calibration error
- Data drift
- Concept drift
- Population shift
- Label shift

### 2. Operational half-life

The period before the deployed system loses practical workflow relevance.

Signals may include:

- Declining use
- Lower recommendation acceptance
- Increased overrides
- Workarounds
- Alert fatigue
- Training decay
- Workflow redesign that bypasses the tool

### 3. Financial or value half-life

The period before realized value falls below a governance-defined threshold.

Signals may include:

- Reduced savings
- Reduced revenue capture
- Higher operating cost
- Lower throughput improvement
- Lower quality improvement
- Lower user productivity

## The central distinction

A technically healthy model can be operationally dead.

That sentence is the heart of the research program.

An AI solution is not valuable because it exists. It is valuable only if it changes decisions, workflows, outcomes, or economics in a way the organization still cares about.

## Proposed value dimensions

This project currently studies six measurement families:

1. Technical performance
2. Adoption and use
3. Workflow impact
4. Financial realization
5. Clinical or operational outcome
6. Governance sustainability

The project does not assume every deployment has every metric. In fact, one of the early research findings is that public reporting is fragmented and often short-term.

## What this framework is not

This is not a claim that AI Half-Life has already been statistically proven as a universal law.

This is not a claim that every AI system follows a clean exponential decay curve.

This is not a replacement for model monitoring, MLOps, governance, risk management, fairness testing, clinical validation, or regulatory compliance.

This is a measurement framework intended to make post-deployment value persistence more explicit.

## Research hypothesis

The working hypothesis is:

Public AI deployment evidence reports launch success, adoption, workflow impact, and some financial impact, but rarely reports long-term value persistence or time-to-value-failure in a standardized way.

If that hypothesis holds, AI Half-Life becomes a useful construct for research, governance, and executive decision-making.
